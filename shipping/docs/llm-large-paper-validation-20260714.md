## 修正后复验

旧问题没有通过放宽校验解决。后续实现了 Card 与 quote ID 动态绑定、论文 evidence ID 动态枚举、数值支持校验、失败中文报告和直接综合显式重跑，并重新生成了 99 条证据。证据置信度分布为：`high=89`、`medium=8`、`low=2`，不再全部默认为 high。

一次论文综合仍暴露出结构性问题：模型需要同时生成 statement 引用集合和 `used` 处置集合，两份状态会发生漂移。最终改为两阶段综合：

1. 模型只生成带 evidence ID 引用的论文分析草稿。
2. 代码从草稿引用集合确定 `used`，不再让模型重复声明。
3. 模型只对未引用证据输出 `redundant/peripheral/excluded` 分类。
4. 代码合并两部分，再执行原 `llm.paper_analysis.v3` 全覆盖校验和数值支持校验。

## 定性结论

**82 Card 大论文的“论文内分批证据抽取 → 直接论文综合 → 全证据处置 → 失败阶段重跑”工程路径已经基本过关。**

这一定性结论只覆盖本论文的直接综合路径，不等于全部大论文路径已经过关。250 Card 论文尚未调用；直接综合超预算后使用的“章节摘要 → 论文综合”路径也尚未经过真实 API 验证。

## 仍需关注的大问题

1. `methods` 仍是无引用字符串。本次输出了 7 条方法描述，但方法字段不携带 evidence ID；与此同时，37 条未被核心结论引用的方法证据被标为 redundant 或 background_only。最终结果因此不能证明每条方法描述来自哪条证据。
2. `unresolved_questions` 仍是无引用字符串。本次 3 条都使用“未说明、未探讨、未分析”等缺失性判断，正是当前系统尚不能可靠证明的内容。
3. 未采用原因集合过窄。相关但未被精简草稿选中的方法和数据细节，只能被迫归入 `background_only` 或 `duplicate_support`；这些标签在人工审核中并不总是准确。
4. 一般语义支持仍只靠模型与人工审核。数值支持已经有确定性校验，但“翻坝转运被验证为短期有效措施”等表述，比所列证据中的“可分担、是措施之一”更强，现有代码不会发现这种程度变化。
5. 章节摘要合同仍同时要求模型生成引用和 used 处置，尚未应用本次两阶段去重状态设计；该路径不能因直接综合成功而视为通过。

## 下一目标

建立 `paper_analysis.v4` 的全陈述追溯合同：

1. `research_focus`、`methods` 和允许保留的 unresolved question 都改成带 evidence ID 的引用对象；没有明确证据时不输出缺失性判断。
2. 未采用原因增加“相关支持细节但未进入精简综合”这一合法分类，避免把方法和数据细节伪装成背景或重复。
3. 增加独立的 statement 语义支持核验阶段，明确区分“原证据直接陈述”和“用于综述时的推论”。
4. 将章节摘要链路改成同样的单一状态来源，再选 250 Card 论文做真实验证。

## 2026-07-15 独立陈述支持核验追加验证

实现了发布前独立核验阶段：所有可自由生成的论文分析陈述都获得稳定 `statement_id`，核验模型只能读取该陈述及其已引用证据。一般分析字段要求直接支持，综述用途允许有依据的推论；部分支持和不支持均阻断发布。人工成功报告和失败报告都显示核验理由，失败请求保留完整陈述清单与模型原始输出。全量 131 项测试通过。

首个真实运行 `llm-v4-nonthink-large82-statement-support-20260715` 在独立核验前被已有数值检查阻断。模型把证据概括为“12 个港口间运价、距离矩阵”，但所列 claim 与逐字引文没有直接陈述数字 12，因此触发 `citation.numeric_fact_unsupported`。只有 evidence relevance 提到 12，而 relevance 不属于事实支持来源。该运行未发布论文分析，失败判定成立。

当前仍不能宣称一般语义支持已闭合；需要显式重跑失败的论文综合请求，使草稿先通过既有合同，再验证新核验器的真实判定。

显式重跑 `llm-v4-nonthink-large82-statement-support-retry1-20260715` 后，新核验阶段真实执行：23 条陈述中 5 条直接支持、4 条合法综述推论、14 条部分支持，运行被阻断且没有发布。部分支持项包括将“小船”具体化为证据未列吨位、把利润下降解释成鲁棒优化保守性、从限定天气影响范围推断陆路运输未被考虑等，说明独立核验确实能发现“有引用但整句不受支持”。

同时核验器把“3 种情景”概括为“多种情景”也判为部分支持，表明首版存在保守过度。已明确允许不扩大范围的等值改述和逻辑蕴含，并收紧综合器：记录层只写原子、直接支持的命题，沿用证据术语，不在方法、发现或局限中追加解释。运行状态新增受约束的显式上游重执行能力，且综合、分类、核验请求全部进入 manifest 执行/复用账本。

## 2026-07-15 显式修订终态

按决策增加独立的 `llm-analysis-revise`。它只接收原始失败分析中的阻断陈述及其原引用证据，允许删除、收窄或拆分，禁止新增 evidence ID；候选必须重新接受全文支持核验，全部通过后才可发布。修订运行不能作为下一次修订来源。

真实运行 `llm-v4-nonthink-large82-explicit-revision1-20260715` 修订了两条阻断陈述，但全文核验响应只返回 47/50 条，按 Schema 失败。没有对模型输出做补齐。随后实现并验证了一次性 support-only 重试：只能复用首轮合法修订，只重新调用核验，且不能形成重试链。
