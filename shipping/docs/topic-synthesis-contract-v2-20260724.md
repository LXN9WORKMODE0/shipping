# 跨论文综合合同 v2 记录

日期：2026-07-24

## 1. 问题结论

五篇论文的 Flash/Pro A/B 连续失败，并不主要说明模型无法理解论文。当前 v1 合同把语义分析和机器账本混在一次输出中，要求模型重复填写：

- 单来源或跨来源类型。
- 章节包含的主题 ID。
- 段落包含的 Evidence ID。
- 细分段落角色。
- 导航文字不得包含任何阿拉伯数字。

这些字段大多可以从论文、主题和综合单元引用中确定性计算。模型在这些字段上失败会阻断整次运行，却不代表主题归组或综合判断本身错误。

## 2. v2 职责划分

模型继续负责：

- Evidence 主题归组和未归组判断。
- 多论文主题的实质关系。
- 综合单元陈述、主题和 Evidence 选择。
- 多论文综合单元的实质类型。
- 章节标题、目的、段落动作和综合单元引用。
- 语料缺口和后续检索方向。

程序负责：

- 一个独立论文来源的主题统一标记为 `single_source`。
- 一个独立论文来源的非缺口综合单元统一标记为 `single_source_context`。
- 章节 `theme_ids` 由该章节段落引用的综合单元求并集。
- 段落 `evidence_unit_ids` 由所引事实综合单元求并集。
- 段落只引用 `corpus_gap` 时生成 `research_gap`，只引用事实单元时生成 `evidence_synthesis`，同时引用两类单元时生成 `evidence_gap_synthesis`。
- 段落 Evidence 与 gap ID 分别从所引综合单元求并集。

原始响应、解析响应和验证后结果分别保存。所有程序派生过程另写入 `audit/contract_derivations.json`，包含输入类型、输出类型、独立论文数、来源综合单元和使用规则。

## 3. 保留的硬门禁

v2 没有放松以下规则：

- 每条 Evidence 必须且只能归组一次，或显式未归组。
- 多论文主题不得标记为 `single_source`。
- 综合单元 Evidence 必须来自其声明主题。
- 多论文综合单元不得标记为 `single_source_context`。
- `corpus_gap` 不得携带 Evidence；事实综合单元不得携带 gap ID。
- 混合事实和缺口的段落必须分别保留 Evidence 与 gap 引用，不能把缺口伪装成 Evidence。
- 每个主题必须进入综合单元并至少进入一个章节。
- 未入纲的额外综合单元不得删除，必须进入 `unplaced_synthesis_unit_ids`、覆盖率和独立审计表。
- 未进入检索方向的缺口必须完整保留，并进入覆盖率与独立审计表。
- 任一门禁失败仍隔离运行，不发布正式结果。

移除了“导航文字不能出现阿拉伯数字”的正则。数字是否得到来源支持不能靠字符形态判断；事实追溯仍依赖 Evidence 和逐字引文，导航字段不能替代 Evidence。

## 4. 历史响应离线回放

将四次不可变历史响应只读投影为 v2 草案，没有重新调用 API：

| 运行 | 主题矩阵 | 提纲 | 程序派生 |
|---|---|---|---|
| Flash v3 | 通过，5个主题 | 通过，8个单元、4节 | 无类型改写 |
| Flash v4 | 通过，6个主题 | 未曾生成 | 3个单来源主题类型 |
| Pro v2 | 通过，5个主题 | 未曾生成 | 无类型改写 |
| Pro v3 | 通过，5个主题 | 通过，14个单元、6节 | 1个单来源综合单元类型 |

Pro v3 回放中还发现 v1 首个错误后隐藏着一个 `paragraph_role=complement`。v2 不再要求模型填写这个装饰性枚举，由综合单元类型生成段落类别，因此该问题不再存在。

离线回放只能证明 v2 能处理已经观察到的结构差异，不能替代新的真实 API 运行。

首次 Pro v2 真实运行 `topic-synthesis-api-5papers-contract-v2-pro-20260724` 进一步暴露了合理的“先陈述锚地建设证据，再指出效果验证缺口”段落。合同据此增加 `evidence_gap_synthesis`，失败运行保持不可变，不作为成功样本。

第二次 Pro 运行 `topic-synthesis-api-5papers-contract-v2-pro-v2-20260724` 生成了一个未进入段落、但所属主题已由其他单元入纲的候选综合单元。v2 保留该单元并写入 `audit/unplaced_synthesis_units.jsonl`，不再为额外候选单元阻断整份提纲；若整个主题没有进入任何章节，仍直接失败。

第三次 Pro 运行 `topic-synthesis-api-5papers-contract-v2-pro-v3-20260724` 在 8 个语料缺口中选择了 6 个检索方向。强制全部缺口转成后续任务与“综述服务于主题”的收束原则冲突，因此未优先缺口保留在 `audit/unprioritized_corpus_gaps.jsonl` 和中文报告中，不再阻断发布。

## 5. 最终合同 API 对比

最终 v2 合同在同一五篇、21 条 Evidence 上的独立运行：

| 模型 | 完整通过 | 延迟 | 按实际缓存估算费用 | 结果 |
|---|---:|---:|---:|---|
| Pro | 2/2 | 74.41秒、74.68秒 | $0.00763、$0.00762 | 均发布正式 JSON 和中文报告 |
| Flash | 0/2 | 14.53秒、22.13秒 | $0.00126、$0.00164 | 一次 Evidence 同时归组和未归组；一次 corpus_gap 缺少 gap ID |

两次 Pro 各约 75 秒、约 1.62 万总 Token。第一次有 1 个跨论文综合单元，第二次没有跨论文综合单元；说明结构稳定性已明显改善，但综合强度仍有模型波动。

两次 Flash 分别约 15 秒和 22 秒，速度优势明确，但失败均涉及程序无法代替模型选择的语义身份，不应自动修正。

覆盖率新增：

- `cross_paper_theme_count`
- `cross_paper_synthesis_unit_count`
- `quality_flags`

结构通过但跨论文综合单元为零时，结果保留并标记 `cross_paper_synthesis_absent`。该标记不触发自动重试，避免通过重复调用碰运气。

## 6. 当前判断

v2 将跨论文模型输出收缩为“语义草案”，代码负责编译可计算的身份和引用账本。它不是失败重试、字段删除兜底或旧输出兼容层；语义和覆盖错误仍直接暴露。

跨论文综合继续默认使用 Pro。Flash 可保留给机械性更强的筛选和抽取阶段，但当前不能替代 Pro 承担主题矩阵与提纲生成。
