# A2主链与全论文池筛选架构决策

日期：2026-08-02

## 决策

根据14篇论文的A2/B2公平对照，后续默认写作链调整为A2。已经实现的B2能力不删除，作为可选功能组件和储备技术库保留。

默认链路调整为：

```text
全论文源目录
→ 源文件清点、去重和处理状态对账
→ PDF/MD到Card批量准备
→ 每篇论文独立轻量主题筛选
→ 全论文池筛选账本
→ 形成当前综述的入选论文集
→ A2完整Markdown直接写作
→ 统一Claim审计
→ 高风险Claim回查与有限修订
→ 导出综述
```

## 全论文池原则

`shipping4/papers`是本轮扩展的源论文目录。2026-08-02实测包含836个文件，其中835个PDF和1个CAJ；按SHA-256计算为834份唯一内容，存在2个两文件重复组。

所有源文件必须进入总账，状态至少属于：

- 内容重复别名；
- 格式不支持；
- 尚待制卡；
- Card已就绪；
- Card运行身份冲突；
- 主题筛选完成；
- 主题筛选失败。

失败、排除和未处理论文都不能从统计中消失。“全部梳理”表示全部论文都经过处理状态登记和主题筛选，不表示全部论文都进入最终综述。

## 筛选层级

第一层为单篇独立筛选，继续使用现有四级合同：

```text
core / supporting / peripheral / exclude
```

该阶段只读取同一篇论文的Card，输出相关性、理由、主题摘要和少量代表Card，不立即抽取Evidence。

第二层为入选集形成。它只读取全部单篇筛选结果，根据综述范围、主题覆盖和模型上下文预算形成明确的纳入/排除清单。A2只读取最终入选论文的完整Markdown。超出预算时必须重新形成入选决策，不允许静默截断全文。

## B2能力定位

以下能力继续保留，可按需接入：

- Paper Understanding：重要论文深度理解；
- Research Landscape和Framework：主题规划与结构辅助；
- Card、Evidence、Source Window：定位与来源回查；
- Claim Ledger：高风险章节的事实边界规划；
- B2审计、裁决和修订：对重要输出进行增强治理。

它们不再是每次生成综述都必须执行的默认长链。

## 当前实施边界

本阶段先建立全论文池清点和独立筛选运行层。834份唯一内容中尚未制卡的论文仍需分批调用MinerU；唯一CAJ文件需要转换为PDF或提供新的解析器。该问题保留为显式阻断，不通过改扩展名或忽略文件处理。
