# Shipping Pipeline 进度记录 - 2026-07-09

## 当前目标

构建一个综述准备 pipeline，让每个中间产物都显式可见：

1. 把论文来源转换为 Markdown。
2. 把 Markdown 解析成可追溯材料卡。
3. 审计材料质量，供人工审核。
4. 在有边界的材料卡集合上运行 LLM 分析。
5. 后续用分析卡作为综述写作的受控输入。

## 已实现

- `shipping/` 是新通用 pipeline 的隔离 workspace。
- MinerU 精确模式 PDF 解析已接入官方 batch API：
  - 申请上传地址。
  - 把本地 PDF 上传到签名 URL。
  - 轮询批量解析结果。
  - 下载结果 zip。
  - 读取 `full.md` 作为标准化 Markdown。
- API 配置从 `shipping/.env` 加载；真实 env 文件已被 git 忽略。
- Markdown-to-card pipeline 输出 `material.v2` 证据卡，包含：
  - `source_span` / `content_ref`
  - `extract`
  - `lead_excerpt`
  - `confidence_flags`
  - `quality_flags`
- 已有面向人的材料审核导出和材料质量审计输出。
- LLM 分析已有受 schema 约束的输出契约，并支持：
  - 确定性的 `mock`
  - `openai-compatible` API provider
  - 用 `--paper-id` 限定单篇论文
  - 用 `--limit` 做小规模冒烟测试

这里的“基本过关”只表示内容完整性、来源追踪、失败隔离和人工审核基础已经闭合，不表示 MinerU OCR 错误、标题污染、图片内容和卡片语义边界已经被修复。上述问题继续作为显式质量信息传给下游。

### Card-to-LLM 当前状态

现有 `llm.analysis.v1` 已能完成单篇论文、单卡或有限卡片的 API 调用，但仍属于接口冒烟阶段：

- schema 是字段说明，不是可执行的正式 JSON Schema。
- 只检查非空，未严格检查字段类型、枚举、未知字段和 ID 唯一性。
- 单卡异常会中断整篇，成功卡和失败卡没有独立账本。
- 未保存逐请求原始响应、prompt 哈希、输入材料快照、实际模型信息和 token 使用量。
- 当前强制一张材料卡对应一张分析卡，会迫使无有效证据的材料也生成观点。
- Markdown 审核勾选没有独立、可校验的审核决策文件。

### 下一目标

下一目标是把 Card-to-LLM 从“能调用”升级为“可审计的论文分析事务”：

1. 以单篇论文及其当前 Card 代际为输入快照。
2. 在同一篇论文内按确定性字符预算分批调用，不跨论文混合。
3. 每张输入 Card 必须得到且只得到一个材料判定，但允许一张 Card 不产生证据单元。
4. 证据单元必须引用输入 `material_id`，引用原文必须能在对应 Card 中逐字验证。
5. 所有批次成功后，再基于已验证证据生成论文级分析；论文级结论必须引用证据单元 ID。
6. 单批失败不丢失其他结果，但整篇运行标记为 `partial`，不发布论文级分析。
7. 不自动补字段、不自动改写非法 JSON、不自动重试；保存原始响应并把问题写入失败账本。
8. 输出中文 Markdown 审核报告和结构化审核决策表；未经完整校验和人工接受的结果不进入后续综述写作。

详细设计和实施顺序记录在 `docs/superpowers/plans/2026-07-13-card-llm-analysis.md`。

## 2026-07-13 Card-to-LLM v2 实施结果

### 已实现

- 仓库根目录已建立独立 `.venv`，依赖固定在 `shipping/requirements.txt`。
- 新增正式 Draft 2020-12 JSON Schema：
  - `llm.evidence_batch.v1`

## 2026-07-14：Card-to-LLM v3 已实施并通过受控真实验证

### 当前生产约束

- 一篇论文是一个隔离分析事务；CLI 必须显式传入 `paper_id`，不允许跨论文组批。
- 模型、provider、上下文窗口、输出上限、Non-think 和 tokenizer revision 只来自固定 model profile。
- 当前 profile：`siliconflow-deepseek-v4-pro`，请求模型 `deepseek-ai/DeepSeek-V4-Pro`。
- 固定官方 tokenizer revision：`0e1a0e5e52aea73055f50fef6f2423db370265b6`。
- 所有请求显式发送 `thinking: {"type": "disabled"}` 和 `max_tokens`；`finish_reason != stop`、返回 reasoning、缺少 token 用量或计划/实际 prompt token 不一致均直接失败。
- 旧字符预算、`LLM_ANALYSIS_MODEL`、mock 生产入口和运行时模型覆盖已删除。

### Token 规划与论文内拆分

- 模型 Card 投影只保留 `material_id/content_kind/heading_path/title/extract/parse_flags`。
- 小中型论文先尝试整篇单批；只有输出预算或上下文预算超限时，才在该论文内部按一级、二级、三级章节逐层拆分。
- 单个 Card 是最小单位；单 Card 超预算直接报错，不按字符估算或截断。
- 论文综合同样执行 Token 预算；直接综合超限时走“章节摘要 → 论文综合”，所有 evidence unit 必须有最终处置。
- 稳定 evidence anchor 由 generation、证据类型和引文生成；evidence unit ID 再绑定规范化 claim，不依赖批次编号。

### 精确引文合同

真实调用证明，让模型自由复制 OCR 文本不能稳定满足逐字审计：模型会把换行替换为空格、合并 OCR 间断字符，或把相邻 Card 的连续语义绑定到错误 Card。

最终采用 `llm.evidence_batch.v4`：

- 代码将每张非图片 Card 的全部非空字符切成不跨行、最长 240 字的精确引文候选，并验证候选坐标、文本和全字符覆盖。
- 模型只选择当前 Card 的 `quote_id`，不重新输出 quote 文本；代码在严格校验后按 ID 回填逐字原文。
- 每张 Card 对应一个嵌套 `material_result`。`evidence` 必须包含至少一个本 Card 证据单元；`context/not_relevant/unusable` 的证据单元必须为空。判定和引用不再是两份可漂移的平铺状态。
- 非法 quote ID、跨 Card quote ID、候选篡改、Card 遗漏/重复都直接失败，不自动修复。

论文综合使用 `llm.paper_analysis.v3`，章节摘要使用 `llm.section_summary.v2`。处置与 reason_code 的合法组合已编码进 JSON Schema，代码仍执行覆盖、引用和处置一致性复核。

现有实现虽然把 `topic` 放入 Evidence Prompt，也允许把 Card 标为 `not_relevant`，但相关性判断与严格 Evidence 抽取发生在同一个请求中，并要求每张 Card 恰好返回一次结果。随后整篇还要依次通过 Evidence claim、字段职责和陈述支持门禁。因此，局部无关内容仍可能阻断整篇，不能满足新的收束目标。

后续默认入口改为独立的轻量三阶段：

1. `topic_scope` 一次读取同篇论文全部精简 Card，只返回论文相关性和少量入选 Card；未入选集合由代码取补集并存档，不逐卡生成模型标签。
2. `selected_evidence` 只对入选 Card 抽取每张最多2条与主题直接有关的 Evidence，继续使用现有逐字引文、数值、限定词和表格合同。
3. `topic_brief` 只读取已验证 Evidence，输出有限数量的主题贡献、可用观点、综述用途和引用注意事项，并生成直接展示原文的中文报告。

默认深度上限为 core 10张、supporting 5张、peripheral 2张、exclude 0张入选 Card；简报观点分别最多8、4、2条。旧 `llm-analysis` 保留为可选深度审计入口，不再作为大多数论文的默认流程。新路径不运行三道全量语义门禁、自动修订和人工裁决链；先通过六篇不同长度的真实论文验证简报效用，只有跨多篇重复出现的问题才允许继续改代码。

完整实施计划位于 `docs/superpowers/plans/2026-07-22-topic-driven-paper-brief.md`。本轮只完成设计纠偏和计划，没有修改运行代码，也没有调用 LLM API。

## 2026-07-22：主题驱动默认路径实现与收束

已实现独立命令 `llm-topic-brief`，不改动上游 MinerU/MD-to-Card，也不替换旧 `llm-analysis`。新默认路径以单篇论文为隔离边界：整篇 Card 只做一次主题定界，核心/支持/边缘论文分别最多选择6/4/2张 Card；每张入选 Card 独立抽取至多1条严格 Evidence；论文简报只读取通过现有逐字引文、数值、限定词和表格合同的 Evidence。未入选 Card 由代码取补集并存档，其解析问题不阻断运行。

真实 API 试运行覆盖3、16、19、23、82、250张 Card。最终规则下的5个验收代际全部完成：16张和19张核心论文各选择6张，23张边缘论文选择2张，82张核心论文选择6张，250张支持论文选择4张。82/250张样本分别忽略76/246张未入选 Card，没有因局部解析标记失败。所有有效请求均 `finish_reason=stop`、reasoning字符数为0，计划/实际输入 Token一致。

开发失败没有隐藏：多 Card 同批造成跨 Card 引文错配，促使 Evidence 改为逐 Card 隔离；定界理由和 Evidence caveat 的事实文本分别污染后续阶段，因此下游 Prompt 只保留必要标签或已验证 claim/引文；简报曾产生强于 Evidence 的改写，因此“可用于综述的观点”现在必须逐字等于一条唯一 Evidence claim。不存在的论文 ID 在 API 前以 `AnalysisInputError` 失败并留档。

报告现明确区分两类内容：定界、贡献、用途和注意事项是导航性模型归纳；只有“可用于综述的观点”及其逐字原文是严格引用链。这样不再为所有自由文本增加语义门禁和人工裁决，同时避免把导航文字误作已验证事实。

完整回归222项全部通过，Python编译检查通过。详细试运行审计见 `docs/topic-driven-paper-brief-pilot-20260722.md`。

当前结论：**主题驱动单篇论文材料简报达到停止条件，可作为默认路径；MD-to-Card、规则表格和单篇深度审计不再继续扩展。** 后续工作应转向跨论文简报聚合，而不是继续追求每篇论文的全面拆解。

## 2026-07-23：未入选 Card 自动回查

用户确认不需要逐篇人工审查后，`llm-topic-brief` 增加无人值守的单轮自动回查。初版简报输出最多2个结构化证据缺口；核心/支持论文存在缺口或首次选卡达到上限时，程序用同篇论文全部未入选 Card 做一次遗漏检查，最多补选2张并逐卡严格取证。边缘/排除论文默认不回查，整个阶段不创建人工裁决表。

配置、简报和运行 manifest 分别升级为 `llm.topic_review_config.v2`、`llm.topic_brief.v2` 和 `llm.topic_review_run.v2`，新增 `llm.topic_revisit.v1`。回查只执行一轮，不递归、不自动重试、不自动换卡。最终观点仍受 `6/4/2` 上限约束，动态 Schema 强制回查 Evidence 替换进入主要观点，并把每个 Evidence ID 与准确 claim 绑定。导航文字禁止阿拉伯数字，避免定界和自由文本污染严格证据。

回查失败不会删除基础简报，也不会混入部分补选；运行明确标为 `completed_with_revisit_failure`，基础简报、候选、部分请求和错误账本均保留。CLI 可以继续批量处理其他论文，但下游必须读取该状态，不能视为回查完成。

真实验证覆盖3、9、15、250张 Card：短文扫描1张后返回 `no_candidate`；15张边缘论文按策略不触发；9张支持论文从5张未入选材料中补选2张；250张核心论文扫描244张并补选1张。两篇补选成功样本的回查 Evidence 均进入最终观点。所有验收请求均 `finish_reason=stop`、reasoning为0、计划/实际输入 Token一致。

过程中保留了首次 Evidence 表格/数值失败、SSL中断、导航数字错绑、主要观点未复制 claim、回查 Evidence 未进入最终观点等失败代际；只对后三类跨样本合同问题修改实现，没有增加解析个例规则。专项审计见 `docs/automatic-card-revisit-audit-20260723.md`。

自动回查专项测试23项、全工程回归230项全部通过，Python编译检查通过。

当前结论：**未入选 Card 已不再是永久死区；程序能够按证据缺口自动回查、严格取证和重排简报，同时保持轻量流程的规模上限。此机制不需要人工审查。**

## 2026-07-23：跨论文主题综合阶段设计

下一阶段确定为“单篇主题简报到跨论文主题矩阵与段落级提纲”，不直接生成正式综述正文。输入采用显式 collection，逐项指定不可变的 `llm-topic-brief` 运行；不根据目录时间自动选择同一论文的最新代际。程序重验单篇简报与 Evidence 引用后，第一次全局 LLM 调用完成主题编码和 Evidence 唯一归组，第二次全局调用形成跨论文综合单元、章节结构和段落论证任务。当前 DeepSeek 模型具有一百万 Token 上下文，v1 不做字符拆批或隐藏层级摘要，超出预算直接失败。

跨论文关系和段落任务继续作为导航性模型推断；最终报告在每项判断下直接回填论文标题、Evidence claim、逐字原文、Card 标题和 Markdown 行号，使人工阅读不需要按 Evidence ID 跨文件查找。代码必须证明每条来源 Evidence 已归入主题或明确未采用、跨论文综合确实涉及至少两篇论文、每个主题进入一个主章节，并记录已归组但未进入提纲的 Evidence。任一阶段失败均不发布正式综合结果，不自动重试或改用半成品。

本阶段明确不重做 Markdown/Card 解析、不重新抽取单篇 Evidence、不递归回查未入选 Card、不生成参考文献格式，也不要求人工裁决。完整设计和实施步骤见 `docs/superpowers/plans/2026-07-23-cross-paper-topic-synthesis.md`。
