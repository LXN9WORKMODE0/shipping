# Pipeline 分阶段与可视化界面备注

可视化工作台的完整 v1 设计见
`docs/ui-design-v1-20260728.md`。首版按只读工作台、分阶段执行、完整流程增强三步实施。

## 当前决策

本轮继续扩大真实论文试验，不立即开发界面。试验按三个独立阶段执行并分别记录：

1. PDF → MinerU Markdown → Card。
2. 已发布 Card → 单篇主题简报与自动回查。
3. 多篇已发布单篇简报 → 跨论文主题综合与提纲。

阶段之间只通过不可变的发布产物、generation ID 和 run ID 连接。上游失败不调用下游；下游重跑不重新解析 PDF。

本轮真实验证已证明跨论文综合可以只读取单篇分析 run ID，不重新触发 PDF 解析或制卡。详细结果见 `docs/staged-validation-6papers-20260727.md`。

## 后续工程方向

### PDF 到 Card

- 支持用论文清单批量运行。
- 批次身份 `paper_id` 与用于范围判定的 `paper_title` 必须拆分；批次前缀不得参与标题匹配。
- 每篇论文独立发布 generation。
- 批次报告汇总解析模式、结构质量、Card 数量、三层覆盖率和失败码。
- 批次验收必须接收显式 collection，只检查清单论文的当前 generation；不得用固定论文数量或扫描全部历史目录代替代际边界。
- 失败论文保留审计记录，但不得暴露旧 generation 给下游。

### 单篇分析与跨论文综合

- 单篇分析显式选择已发布 Card generation。
- 跨论文综合显式选择已完成或允许部分完成的单篇分析 run。
- 两个阶段均可独立重跑，不隐式触发 PDF 解析。

### 可视化界面

界面只作为现有运行和审计产物的管理层，不把解析、证据校验或综合合同重写到前端。首版至少需要：

- 论文与批次列表，以及各阶段状态。
- 分别显示 PDF→Card、单篇分析、跨论文综合三个阶段的输入代际、当前状态和可独立执行按钮。
- PDF/Markdown、Card、Evidence、单篇简报和综合提纲的逐级查看。
- 原文位置、逐字引文、质量标记和失败码的同屏展示。
- 单篇分析至少区分 `completed`、`completed_with_failures`、
  `completed_with_revisit_failure` 和 `failed`，不得把部分完成显示成完全成功。
- 对 `completed_with_failures` 直接展示失败 Card 的标题、原文位置、完整内容和合同错误，
  不要求用户根据 Evidence ID 反查文件。
- 独立启动某一阶段，并显式选择输入 generation/run。
- Token、请求数、阶段耗时和失败率统计。

首版界面不承担人工修正模型 JSON，也不自动越过失败屏障。

主题：三峡船舶积压形成机制、疏导策略与枢纽扩能。

样本包含仿真研究、预测模型、停航积压估算、运行组织和枢纽扩能对策，先单独验证 PDF 到 Card，再决定进入后续分析的论文集合。
