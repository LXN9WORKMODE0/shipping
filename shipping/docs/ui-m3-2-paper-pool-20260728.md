# UI M3.2：论文池解耦实施记录

日期：2026-07-28

对应架构决策：`docs/paper-pool-decoupling-20260728.md`

## 已实现

### 逐文件导入

`POST /api/projects/{project_id}/sources` 由整批成败改为逐文件结果：

- `imported`：写入受管来源目录并加入当前 collection。
- `skipped_duplicate`：返回重复来源对应的已有或本批论文 ID。
- `failed`：返回稳定错误码和中文错误信息。

同批有效文件不会再被重复项、空文件、缺少论文 ID 或不支持格式阻塞。只有项目 revision 冲突和发布阶段异常仍属于请求级失败。零文件导入成功时不提升项目 revision。

### Job 汇总状态

Job 新增终态 `completed_with_failures`：

- 全部论文成功：`completed`
- 至少一篇成功且至少一篇失败：`completed_with_failures`
- 零篇成功或系统级异常：`failed`

Card 和单篇分析 Job 均采用该逻辑。完整流程保持严格语义，不因本次改造而改变。

### 论文池状态

项目汇总会读取最新单篇分析 Job 的逐论文结果。失败分析不发布为可综合 run，但对应论文会显示为 `failed`，错误码进入论文摘要。成功分析 manifest 仍是 Evidence 的唯一事实来源。

### 界面

- 导入对话框显示导入、重复跳过、失败三类计数和逐文件详情。
- 重复来源直接显示所对应的论文 ID。
- Job 的部分成功状态显示为黄色“部分完成”，不再显示成整批失败。
- 论文池新增“选择已制卡”操作。
- 状态筛选新增“Card 已就绪”和“处理失败”。
- 原“完整流程”改名为“严格完整流程”，与日常分阶段操作区分。

## 审视

本轮已经解决“单篇失败拖垮整批”和“重复文件拖垮整批”两个主问题。当前三个阶段在操作和状态上可以独立使用：

1. 先形成论文来源池。
2. 对任意子集制卡。
3. 对已制卡子集做单篇分析。
4. 从当前可用分析结果中运行综合。

仍保留的明确约束：

- 项目同一时间只运行一个 Job，尚未实现并行调度。
- 取消仍是协作式取消的后续任务，本轮未改。
- Windows 传统路径长度限制可能影响位于极深测试目录下的临时产物。真实项目当前工作区路径未触发该问题；后续如调整工作区层级，应单独验证。
