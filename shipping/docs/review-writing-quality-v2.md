# 综述写作质量机制 V2

## 本轮目标

本轮只处理三个问题：相同或近似事实的证据更新、防御式写作、从成熟学术写作方法中固化可复用规则。综述主线与主题结构继续使用现有层级研究景观，不在本轮重构。

## 新流程

```text
研究景观 + Paper Understanding + 明确参考文献目录
→ 论点与证据更新计划
→ 结论先行的综述正文
→ 引用覆盖与论点覆盖审计
```

论点计划是正文前的正式输入，不是旁路提示。每个论点记录事实类型、结论、论文年份、证据角色、更新理由和是否需要边界句。正文只能读取整份论点计划批准的论文投影，不能重新接触未入选论文；段落允许综合计划内不同论点的证据，跨论点引用单独审计。所有计划论点必须至少进入正文一次。

## 证据更新规则

- 当前状态、政策状态和工程状态：只有对象、指标、口径和范围可比时，采用最新年份证据作为当前事实；旧证据可保留为历史背景或佐证。
- 历史事实：保留最接近事件或原始观察的来源，不用新论文机械替换。
- 方法结果、机制和预测：只有场景、指标和验证方式可比时才直接比较；不可比证据并列保留。
- 缺少任一论文年份时，写作运行直接失败并列出论文，不假装完成时效判断。

## 写作规则

- 每段第一句直接提出结论，随后综合证据。
- 禁止逐篇摘要式罗列。
- 正文不保留“证明、普遍、根本”三个泛化词。供应商原始响应完整留档；验证前只按固定映射做术语规范化，替换项和次数写入 `academic_term_normalization.json`，不改论点、数字、引用或结构。
- 边界只在会改变结论含义、适用对象或行动判断时出现，并限制为论证末尾一句。
- 保留结果类型和验证水平的事实约束，不能把仿真、建议或算法测试写成工程实施效果。

## 方法来源

本轮参考并转化了本机可用的 `scientific-writing`、`literature-review` 和 `nature-writing` 方法：两阶段提纲到正文、主题综合、段落连贯、近期证据优先。程序不在运行时读取这些 skill，规则已经写入数据契约、提示词和校验逻辑，避免环境依赖。

## 真实验证

2026-08-14 已为冻结的 49 篇集合生成 `hierarchical-scale49-writing-references-20260814-v3`：49 篇均有发表年份，缺失数为 0；11 条解析器未能提取的年份通过带来源说明的显式修订表补入，修订输入随运行归档。

真实论点规划使用 DeepSeek V4 Pro，输入 185049 tokens、输出 6276 tokens。验证过程中暴露并修正了三类问题：过去观察期被误标为当前状态、工程方法结果被误标为工程当前状态、背景相关论文被误标为同指标佐证。最终共享论点计划为 `hierarchical-writing-quality-ab-20260814-v5--baseline`。

最终 A/B 为 `hierarchical-writing-quality-ab-20260814-v17`，两版共用同一论点计划、同一批准证据投影和同一术语规范化：

| 指标 | 基础版 | Skill-guided |
|---|---:|---:|
| 正文字符数 | 7316 | 6327 |
| 段落数 | 32 | 26 |
| 平均段长 | 218.4 | 230.5 |
| 多来源段落比例 | 65.62% | 57.69% |
| 防御性标记次数 | 0 | 0 |

定性结论：Skill-guided 版的章节开头更直接，重复铺陈更少，按观点推进的特征更清楚；代价是正文压缩约 13.5%，多来源段落比例下降约 8 个百分点。它不是无条件优于基础版。当前默认仍采用 Skill-guided，但保留 6000 字最低长度、论点全覆盖、计划外论文硬拒绝和跨论点引用审计，防止“精炼”退化为证据省略。

## 运行工具

- `scripts/build_hierarchical_reference_catalog.py`：从冻结层级景观生成题录，可接收带来源的年份修订表。
- `scripts/compare_hierarchical_writing_profiles.py`：在同一论点计划上运行基础版和 Skill-guided，可复用已完成基础版；任一侧失败时仍生成对比报告。
- 最终正文和审计位于 `workspace/_hierarchical_review_writing/runs/`，A/B 报告位于 `workspace/_hierarchical_review_comparisons/runs/`。
