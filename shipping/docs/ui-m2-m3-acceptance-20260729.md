# 可视化工作台 M2/M3 总验收

日期：2026-07-29

## 结论

M2/M3 工作台已形成可运行的分阶段论文池：

```text
项目与来源
  -> PDF/Markdown 到 Card
  -> 单篇主题分析
  -> 显式选择 run 后跨论文综合
```

各阶段可以独立运行。单篇失败不再阻断同批成功论文，综合只使用用户显式选择的可用分析 run。

## 当前运行原则

- PDF/Card 准备、单篇分析和跨论文综合是独立阶段。
- 一个论文分析任务只处理一篇论文；大论文只在论文内部按章节拆批。
- 批量导入、Card 和单篇分析允许部分成功。
- 取消和服务中断不伪造论文失败。
- 重跑创建新 Job 和新 run，不复用旧代际。
- 综合输入由用户显式选择，不隐式采用“最新成功”。
- 归档项目保持全部产物可读，但不能继续写入。

## 剩余风险

- PDF 到 Markdown 的上限仍由 MinerU 原始解析质量决定。
- 配置健康只证明本地配置完整，不证明外部 API 当前可用。
- 服务异常退出时，只承认已经原子写入 Job 账本的逐论文结果。
- 历史底层 run 与工作台 Job 会同时出现在运行列表；治理总量已去重，但历史列表仍较长。
- 移动端有响应式实现和构建检查，本轮未完成真实移动浏览器截图验收。

## 后续决策点

M2/M3 功能路线已经收束。下一步不应继续自动扩展工作台能力，需要在以下方向中选择：

1. 用新的真实 PDF 论文池做一次从来源到综述的整体验收。
2. 回到综述内容质量，评估单篇分析和跨论文综合是否满足实际写作。
3. 将当前功能分支合并到 `main`，形成第一个稳定版本。
