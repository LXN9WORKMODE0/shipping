# 自动化文献综述 Pipeline 项目说明与阶段性问题报告

## 一、项目背景

本项目起源于一个尝试性设想：将文献综述中重复、机械但又需要保留证据链的工作尽可能自动化。

最初设想的完整流程是：

```text
生成检索方向
→ 人工获取论文
→ PDF解析为Markdown
→ Markdown拆分为结构化材料Card
→ LLM进行单篇论文分析
→ 跨论文主题综合
→ 自动生成综述正文
→ 人工审查和修改
```

预期中，人工主要负责获取和筛选论文，程序负责材料整理、证据抽取、主题综合和初稿生成。

项目并不追求完全替代研究者，而是希望解决三个现实问题：

1. 大量论文难以逐篇细读和整理。
2. LLM直接阅读大量论文时，分析过程和信息来源隐藏在上下文中，结果难以审核、复用和复现。
3. 同一批论文可能服务于不同综述主题，需要形成可复用的论文材料池，而不是每次从PDF重新开始。

## 二、项目目标的变化

项目早期偏向“完整拆解每篇论文”，希望建立从原文到章节、段落、Card和Evidence的严格映射，并证明没有静默遗漏。

实际开发中逐渐发现，这个目标成本很高：

- PDF格式和排版差异很大。
- MinerU等解析器对部分中文旧论文、表格、OCR文本和复杂版面处理较差。
- Markdown标题层级并不稳定。
- 有些论文会丢字、错行、表格未闭合或把正文识别成其他结构。
- 为少量可能根本不会进入综述的细节投入大量人工裁决，不符合最终目的。

因此项目发生了一次重要思路转折：

> 论文解析和Card不再追求完美复原论文，而是为综述主题提供足够可靠、可回溯的材料基础。

同时，系统从“一次运行必须处理全部论文”调整为“论文池”模式：

- PDF到Card是独立环节。
- 单篇论文分析是独立环节。
- 一篇论文失败不阻断其他论文。
- 已成功处理的论文可以长期保存在论文池中。
- 综述任务从论文池中选择可用论文，不要求所有输入文件都成功。
- 未入选Card不会被永久丢弃，程序保留自动回头检查机制。

## 三、现有数据素材

当前项目已经积累了一批真实中文论文，主要存放在项目的论文目录中，内容包括三峡航运、船闸运行、船舶调度、船型标准化、坝前转运和通航能力等。

目前完成过一次较完整的14篇论文验证，主题为：

> 三峡枢纽通航能力的提升方法

这14篇论文的时间跨度为1997年至2025年，包括：

- 行业和学术期刊论文；
- 船闸运行与调度研究；
- 船舶大型化和标准化研究；
- 智能管控平台研究；
- 3篇武汉理工大学学位论文；
- 仿真优化和综合运输组织研究。

14篇论文合计形成：

- 804张Card；
- 57条单篇Evidence；
- 47条Evidence进入跨论文主题；
- 41条Evidence进入综述提纲；
- 13篇论文最终被正文引用；
- 1篇论文未进入正文，但没有被静默丢弃；
- 10篇单篇分析存在局部Evidence抽取或自动回查失败，这些状态均被保留。

需要强调：这14篇论文是围绕特定主题定向选择的工程验证样本，并不是经过系统检索、去重、纳排和质量评价形成的系统综述语料。

## 四、当前技术流程

### 1. PDF解析

系统已经接入MinerU API，并配置使用精确模式，将PDF转换为Markdown。

这一层的结论是：

- 大部分论文可以获得可用Markdown。
- 部分论文存在OCR错字、字符缺失、段落混乱和表格问题。
- 解析质量不能保证完全一致。
- 解析问题会记录，而不是通过猜测或静默兜底掩盖。
- 对综述材料准备而言，目前可视为基本可用，但不能认为原文完全无损。

### 2. Markdown转Card

程序将Markdown识别为摘要、关键词、正文、表格、参考文献等区域，再拆成带有来源坐标的Card。

Card主要保存：

- 论文身份；
- 标题路径；
- 材料类型；
- 原文摘录；
- Markdown行号；
- 解析质量标记；
- 运行代次和指纹。

这部分经过多轮真实论文测试，已经达到“可作为后续LLM分析输入”的水平，但仍然有明确限制：

- 解析错误会传递到Card；
- 无标题正文和异常结构曾出现归属问题；
- 表格、OCR间断和原文坐标仍可能不理想；
- “基本过关”指能支撑主题分析，不代表完全无静默遗漏。

### 3. 单篇论文主题分析

每篇论文始终作为一个隔离任务，不会把多篇论文混进同一个单篇分析Prompt。

当前逻辑是：

1. 根据综述主题判断论文属于核心、支撑、外围或排除。
2. 从该论文Card中选择少量最相关材料。
3. 从入选Card中抽取带逐字引文的原子Evidence。
4. 生成单篇Paper Brief。
5. 检查未入选Card中是否存在遗漏的重要维度。
6. 保存失败Card、原始响应、Token使用和回查结果。

大论文优先整篇分析；超过Token预算时，只在论文内部按章节拆分。模型使用DeepSeek V4系列，支持1M上下文和Non-think模式。项目对Pro和Flash做过初步API测试，本次14篇综合和正文草稿主要使用Pro。

### 4. 跨论文综合

程序将多篇论文的Evidence汇总，依次完成：

- 有限主题矩阵；
- Evidence到主题的多标签归类，每条最多进入两个主题；
- 跨论文综合单元；
- 研究分歧和互补关系；
- 语料缺口；
- 章节和段落级提纲。

该阶段有严格合同：

- Evidence不能静默遗漏；
- 单篇多条Evidence不能伪装成跨论文共识；
- 综合单元必须保存来源论文和Evidence ID；
- 输出结构错误时允许一次严格合同修正；
- 不自动补造ID，也不通过放宽Schema让错误通过。

14篇验证中成功形成8个主题、16个综合单元、7个章节和12个段落任务。

### 5. 正文写作

当前正文写作采用一次全局LLM调用。

模型收到：

- 锁定的章节提纲；
- 段落任务；
- 41条Evidence的claim；
- 论文标题；
- Evidence类型、置信度和少量限制；
- 语料缺口；
- JSON Schema和写作约束。

模型不直接看到：

- 完整PDF；
- 完整Markdown；
- Card全文；
- Evidence逐字引文；
- 原论文论证过程；
- 大部分未入选Card；
- 完整Paper Brief上下文。

本次写作过程中，41条Evidence claim合计只有约2441个字符，却要求模型生成5000至8000字正文。最终首版正文约3559字，摘要、正文和结论合计约4330字。

## 五、当前产出

目前已经形成：

- 14篇论文的PDF、Markdown和Card材料；
- 单篇论文Paper Brief与Evidence；
- 跨论文主题矩阵和综合提纲；
- 一版中文综述草稿；
- 14篇论文的完整基本题录；
- BibTeX和参考文献表；
- 正文引用编号；
- Evidence索引；
- 运行审计、失败记录和人工审核材料；
- 支持论文池、独立分析和综述任务的可视化界面；
- Git版本管理和远端仓库。

参考文献链已经基本闭合。正文中引用的13篇论文都有连续编号，14篇输入论文的题录字段均达到当前完整性合同。

## 六、当前正文质量

现有正文不是完全无效。它已经做到：

- 按问题和方法组织，而不是逐篇复述；
- 覆盖运行挖潜、智能调度、船型适配、工程扩能和运输组织；
- 文中数字基本能回到对应Evidence；
- 能保留不同论文对新建通道的不同意见；
- 论文和Evidence来源可以追溯。

但它还不能作为正式综述直接使用。主要问题包括：

- 14篇定向样本被写成“系统综述”；
- 两篇论文被概括成“学界共识”或“主流观点”；
- 算法计算效率被外推成闸室利用率和实际通航能力；
- 模型测算、工程建议和拟建平台被写成实践效果；
- 历史数据、早期预测和当前状态没有充分区分；
- 本次样本未回答的问题被写成整个领域的研究空白；
- 文章结构完整，但论证较薄，段落之间存在较多概括性连接语。

目前对正文的定性评价是：

- 作为Pipeline验证产物：基本合格；
- 作为研究者继续修改的内部初稿：可用；
- 作为可以提交或公开的综述：不合格；
- 综合质量约为6/10。

## 七、当前最核心的问题

目前系统的问题已经不再主要是PDF解析，而是写作阶段的信息瓶颈。

现有设计希望通过Evidence保证可审计性，但在写作前把论文压缩得过于严重：

```text
完整论文
→ 804张Card
→ 57条Evidence
→ 41条正文Evidence
→ 2441字原子claim
→ 要求生成完整综述
```

模型虽然受到严格事实约束，却失去了形成高质量综述所需要的上下文：

- 不知道论文如何提出问题；
- 不知道方法和结果之间的论证过程；
- 不知道作者结论的具体边界；
- 难以比较不同研究的研究对象和指标口径；
- 难以形成有深度的跨论文讨论。

这解释了为什么当前结果可能不如直接把PDF或完整Markdown交给高级模型：直接阅读论文的模型拥有更丰富的上下文，可以形成更自然的论述；当前模型只能用少量离散Evidence拼装文章。

## 八、拟议的思路调整

目前较合理的方向不是废弃Card和Evidence，而是重新定位它们：

> Card和Evidence用于论文池、检索、引用、审核和事后核验，不再作为正文模型唯一可见的论文内容。

新的写作方案可改为：

1. 使用Card和Evidence完成论文管理、主题筛选和提纲生成。
2. 按章节构造丰富写作材料包。
3. 材料包包含相关论文Markdown、完整Card、Paper Brief、Evidence逐字引文、论文题录和上下文段落。
4. 让LLM在充分阅读材料后完成章节写作。
5. 写作完成后，再由程序逐项检查事实、引文和Evidence边界。
6. 最后进行一次全文编辑，只统一术语、结构和重复内容，不允许新增事实。

这可以概括为：

```text
原方案：先压缩并限制信息，再让模型写作
新方案：提供充分信息让模型写作，再进行证据审计
```

## 九、希望向外部请教的关键疑惑

### 1. 项目定位

这个系统应该优先追求哪一种目标？

- 高度可审计、可复现，但正文需要较多人工修改；
- 自动产生接近可交付的综述，允许更宽松的中间结构；
- 论文材料管理与写作分离，系统只负责准备材料和审计，最终写作主要交给高级模型。

### 2. Evidence是否被使用错了

Evidence适合作为最终写作的唯一输入，还是更适合作为引用锚点和事后核验依据？

当前经验表明，Evidence-only写作可能天然损失论文的论证结构和语义上下文。

### 3. 写作上下文应该采用什么粒度

可考虑三种方式：

- 将全部论文Markdown一次交给1M模型；
- 按章节向模型提供相关论文全文；
- 提供Paper Brief、相关Card和必要上下文段落。

需要判断哪种方式在质量、成本、可扩展性和引用准确率之间更合理。

### 4. 是否需要继续追求MD-to-Card的完整性证明

如果最终写作模型仍会读取完整Markdown，那么Card是否只需要满足检索和定位要求，而不需要承担“完整表示论文”的责任？

继续追求逐行完整归属是否具有足够实际价值？

### 5. 如何评价自动生成综述的质量

目前可以检查引用和事实来源，但缺乏稳定的正文质量评价体系。需要考虑：

- 跨论文综合程度；
- 事实准确性；
- 证据强度匹配；
- 结构完整性；
- 研究分歧呈现；
- 对综述主题的回答程度；
- 人工修改成本。

是否能设计一套既可自动运行、又与研究者判断一致的评价方法？

### 6. 是否需要文献质量分级

目前Evidence来自不同类型论文，包括短篇行业论文、学位论文、历史系统研究和仿真研究，但正文对它们的权重基本相同。

是否应建立文献质量、研究类型和证据等级，使模型区分：

- 历史实测数据；
- 模型或仿真结果；
- 算法性能；
- 工程建议；
- 平台设计；
- 已实施措施；
- 作者观点。

### 7. 如何控制人工审查成本

此前尝试过较详细的人工Evidence裁决，但一篇论文就会产生较大审核负担，扩展到几十篇后难以承担。

需要确定人工只应介入哪些问题，例如：

- 影响综述核心结论的证据冲突；
- 高风险数字；
- 新建工程或政策建议；
- 模型无法确定的论文身份和引用；
- 最终正文中的强结论。

### 8. 直接把论文交给LLM是否已经足够

这是目前最值得验证的问题。

如果使用1M上下文高级模型，将14篇规范化Markdown、主题要求和引用元数据一次提供，是否已经能生成明显优于当前Pipeline的综述？

如果答案是肯定的，那么本项目的价值可能应收缩为：

- PDF解析和论文池；
- 单篇材料索引；
- 主题检索和选文；
- 引用与参考文献；
- 生成后事实核验；
- 运行记录和可视化管理。

而不必在写作前把论文压缩成过度严格的Evidence体系。

## 十、建议的下一项验证

建议使用同一批14篇论文完成一次对照实验：

- 方案A：将14篇完整Markdown直接交给DeepSeek V4 Pro生成综述。
- 方案B：采用新的章节级丰富材料包生成综述。
- 方案C：保留当前Evidence-only正文作为对照组。

比较三个结果的：

- 可读性；
- 综合深度；
- 事实错误；
- 引用准确率；
- 证据越界数量；
- 研究分歧呈现；
- 人工修改时间；
- Token和API成本。

这项实验可以帮助决定项目最终应成为“自动综述写作系统”，还是“论文材料准备、检索和审计系统”。目前这是比继续细化Card规则或修改现有草稿更关键的架构决策。
