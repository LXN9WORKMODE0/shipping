### 暴露的问题

1. 首轮给论文 ID 加试验前缀后，Arena 论文被判定为 `parse.document_scope_ambiguous`。原因是当前 `paper_id` 同时承担工作区身份和预期标题，试验前缀参与了标题匹配；MinerU 又把标题中的 “Arena” 丢失，进一步降低相似度。使用真实标题作为论文 ID 后完成解析。这说明后续批处理清单应拆分 `paper_id` 与 `paper_title`，而不是放宽标题匹配。
2. 反脆弱学位论文首轮在 `region_to_block_ratio=0.997416` 时被 `coverage.materialization_failed` 拒绝。唯一未进入 Block 的是正文内部一级标题。根因是解析器把所有 H1 都当成主标题跳过。修改后只跳过所选文档范围的主 H1，内部 H1 作为章节结构，并补充学位论文反例测试。重跑后覆盖率为 1.0。
3. 首轮失败工作区和审计记录均保留；最终结果来自新的 generation，没有覆盖或伪装首轮失败。

## 第三阶段：跨论文综合

综合输入只引用 5 个可用单篇运行 ID，不重新读取 PDF 或重新制卡。两个 `completed_with_revisit_failure` 来源被显式标记为部分来源。

### 首轮失败

运行 `staged-synthesis-5papers-20260727` 在主题映射阶段失败，错误码为 `evidence_map.assigned_and_unassigned`。模型把同一 Evidence 同时放入一个主题和 `unassigned_evidence`。契约拒绝是正确行为。

提示合同随后明确：`assignments` 与 `unassigned_evidence` 是互斥终态；认为证据重复时也必须二选一，不由代码自动删除冲突项。对应测试通过后使用新运行 ID 重试。

## 阶段性判断

1. 三个阶段已经在真实产物上实现运行隔离：下游重跑不触发上游，综合失败不污染单篇结果。
2. PDF 到 Card 在本轮 6 篇异构论文上基本通过，但批次身份与论文标题必须在后续批处理接口中拆分。
3. 大论文选择性分析和自动回查路线可用；严格失败主要来自模型引证服从性与回查简报约束，不是上下文长度。
4. 跨论文综合可以形成可审计的主题、综合单元和提纲，但模型偶发输出矛盾，需要依靠合同拒绝和新代际重跑。
5. 可视化界面应建立在现有 generation、run、审计文件和人工可读报告之上，不应把失败修正逻辑移到前端。
