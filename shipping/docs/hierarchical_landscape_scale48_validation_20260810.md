# 48 篇论文扩容与多主题验证报告

日期：2026-08-10

## 一、验证结论

本轮将层级式综述分析从少量论文扩大到 **48 篇论文、7 个主题簇**，并完成了论文理解、主题内归纳、跨主题归并、缺口回看和增量重算的真实 DeepSeek 调用。

定性结论是：**当前流程已经具备生产试用条件，能够处理几十篇论文和多个主题，并在局部失败后复用成功结果继续运行；但尚不能视为完全无人值守。** 主要剩余问题不是上下文容量，而是外部接口的偶发传输失败、严格结构化输出的波动，以及长任务缺少阶段级实时进度和更细粒度恢复。

## 二、验证范围

- 筛选母池：823 篇论文
- 本轮进入层级分析：48 篇
- 主题簇：7 个
- 同时进入多个主题的论文：10 篇
- 局部研究维度：41 个
- 最终全局研究维度：7 个
- 最终跨主题关系：8 条
- 最终回看请求：5 条
- 局部维度归并覆盖率：41/41，100%

7 个主题覆盖运行基线、联合调度、水力与泥沙、安全可靠性、船型适配、工程扩能和能力评估等不同问题，规模和语义差异明显高于此前的小样本验证。

## 三、关键改造

### 1. 全局归并改为分阶段执行

原方案要求模型一次完成全局维度归并、跨主题关系和回看请求。论文与主题扩大后，模型容易出现维度重复、遗漏、同主题伪装成跨主题关系，以及关系两端归属错误。

现在拆成三步：

1. 只完成全局维度归并，并逐项决定每个局部维度属于哪个全局维度。
2. 从主题簇组合中选择最多 8 对值得建立关系的主题。
3. 每一对主题独立生成一条关系，只向模型提供这两个主题的局部维度。

局部维度分配表成为唯一事实来源。全局维度包含哪些局部维度、论文和主题簇均由程序回填，不再让模型重复抄写这些集合。

### 2. 使用短别名降低长标识符复制错误

提交模型时将局部维度映射为 `D0001` 形式的短别名，返回后由程序恢复正式 ID。程序拒绝最终产物中残留别名，并校验每个局部维度恰好出现一次。

### 3. 跨主题关系采用隔离约束

关系生成时一次只处理一对主题。程序校验关系两端的维度确实分别属于指定主题；若模型只把左右顺序写反且归属可以唯一证明，则按主题顺序规范化。关系文字中的“前者、后者、两者”等指代会替换为明确主题名称，避免脱离上下文后不可读。

### 4. 增量回看只重算受影响主题

回看候选经过论文理解和支持程度判断后，只有获得足够支持的论文才会提升。提升后只重算受影响主题，其他主题直接复用上一代结果。本轮最终提升 1 篇论文，重算 3 个主题，复用 4 个主题。

## 四、模型选择观察

使用同一组 4 篇论文比较 DeepSeek V4 Flash 与 Pro：

- Flash：3/4 成功，1 篇结构化输出失败。
- Pro：4/4 成功。
- 在语义上，Pro 能把物理模型试验识别为实验或基准验证；Flash 更容易笼统归为仿真。

因此本轮正式扩容使用 Pro。Flash 可以用于低风险筛选或成本敏感任务，但当前不建议替代 Pro 承担 Paper Understanding 主链。

## 五、真实吞吐量

### Paper Understanding

- 新增验证论文：18 篇。
- 第一代成功 11 篇，7 篇主要因 SSL EOF 或响应不完整失败。
- 第二代成功累计 17 篇，剩余 1 篇为方法类别不符合 Schema。
- 第三代成功 18/18。
- 第一代成功论文平均耗时约 38.4 秒/篇。
- 一篇输入约 148,811 token 的长论文在约 52.2 秒内完成。

这说明 1M 上下文容量足够，论文长度不是当前主要瓶颈；外部连接可靠性和串行调用次数更影响总耗时。

### 全局归并

最终增量全局归并约 90 秒完成。其中包括一次全局维度归并、一次关系对选择和 8 次关系详情调用。最终覆盖率为 100%。

### 回看与增量重算

- 回看：8 个请求中 7 个匹配到候选，形成 15 个候选分配、14 篇唯一候选论文，耗时约 67 秒。
- 增量第一代：运行约 13 分钟，7 篇候选理解失败，两个主题输出违反精确 ID 或归属约束，因此未进入全局归并。
- 增量第二代：复用成功结果后约 8 分钟完成；10/15 个候选分配完成裁定，1 篇获提升，3 个主题重算，4 个主题复用，并成功完成全局归并。

第二代状态为 `completed_partial`，原因是仍有 5 个候选分配未完成理解，而不是主链或最终归并失败。

## 六、语义质量判断

最终全局维度能够形成可用于综述提纲的稳定结构，主要包括：

1. 通航能力评估、瓶颈与需求预测。
2. 多目标联合调度与运行优化。
3. 新通道、船闸扩建及航道工程。
4. 水文、水流和泥沙条件。
5. 安全、维护与可靠性。
6. 船型适配、吃水与交通组织。
7. 运行管理及相关综合议题。

跨主题关系中多数能够指出约束传递、评价参数共享或工程与运行之间的联系，但少数关系仍偏弱或表述生硬。因此它们适合作为**写作时的结构提示和检索线索**，不应未经证据核对直接改写成正文事实。

回看机制的语义表现符合设计目标：能够召回与稳健调度、需求预测、组合策略和建设期保障相关的候选，也能明确拒绝只能提供背景、不能回答具体缺口的论文。这避免了为了补缺口而强行提升低相关论文。

## 七、当前边界和后续优先级

### 已达到

- 数十篇论文、多主题和论文多重归属可运行。
- 全局归并具备逐项完整性证明，不再依赖模型自行维护集合。
- 跨主题关系数量受控，并通过主题对隔离减少归属错误。
- 回看候选不会自动污染主材料池，只有通过判断的论文才提升。
- 失败续跑可复用论文理解、候选裁定和未受影响主题。

### 尚未完全解决

1. 外部 API 偶发连接中断仍会产生部分完成状态，需要再次续跑。
2. 长任务执行期间缺少可见的阶段进度，用户只能等待最终状态。
3. 全局归并内部尚未做到阶段级恢复；若后半段失败，可能重复前面已经成功的全局调用。
4. 严格 ID 和贡献归属仍可能被模型写错，当前策略是显式失败并重试，不做模糊匹配。
5. 关系层的语义可靠度低于维度归并层，应保持辅助地位。

## 八、最终判断

这次扩容证明主架构成立：**论文池可以先广泛筛选和理解，再按主题形成局部研究景观，最后做受控的跨主题综合；后续证据补充只增量影响相关主题。** 它已经不再受“旧综合器一次吞不下所有论文”的结构性限制。

下一阶段不需要继续扩大单次 Prompt，而应优先把阶段进度、失败论文重试入口和全局阶段级恢复接入可视化界面。语义上则应使用最终维度和局部证据生成综述正文，并把跨主题关系当作候选写作线索，由引用验证环节决定是否采用。
